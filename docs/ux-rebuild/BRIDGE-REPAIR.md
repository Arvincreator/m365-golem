# Bridge 本機連線修復（2026-09-07）

使用者另行要求修復 Bridge；本次範圍超出原 M0/M1 的控制層凍結，但不變更 M365 控制、工具核准或站台政策。

## 原因與修正

- Edge 保留舊安裝包的 Native Host，使用舊共用通道。已備份舊啟動器，將舊入口轉接目前專案，並僅重啟宿主。
- 封裝應用與 Edge 對 AppData 的存取可能被 Windows 導向不同檔案。現場觀察到同一路徑的政策摘要不同及 IPC 驗證失敗。
- 將 IPC 憑證獨立放在明確的使用者目錄 `.m365-golem/bridge-runtime/`，由 MCP 設定與 Native Host 的 `secret-path.local.txt` 共用同一絕對路徑。只由既有 MCP owner 生成憑證，沒有複製瀏覽器憑證。
- 安裝程式產生此路徑設定；設定檔被 Git 忽略。政策與稽核檔路徑保持原樣，未擴大站台或寫入授權。
- 分發測試改依發布使用的 Git 檔案清單掃描，失敗只列檔名，避免將忽略的本機狀態與敏感內容輸出到測試結果。

## 證據與限制

- 7 項分發測試通過；安裝程式以 PlanOnly 驗證，不重跑整套安裝。
- 使用 Golem 現有 MCP 設定與其共用通道執行 status：`extensionOnline=true`、`replyOk=true`，無 IPC 驗證錯誤。
- 未指定站台的 status 不證明 Microsoft 登入可用；另一次指定站台的唯讀探測逾時，未證明 SharePoint 檔案讀取或下載成功。
- 現場啟動器備份、MCP 設定備份及路徑設定僅留本機，不納入 PR。可由備份回復設定；回復時須同步兩端路徑並重連，不能只改其中一端。
